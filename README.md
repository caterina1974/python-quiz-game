# 나만의 파이썬 기초 퀴즈 게임

Python 기초 문법을 퀴즈로 복습하고, 문제와 최고 점수를 JSON 파일에 저장하는 콘솔 프로그램입니다.

- **GitHub 저장소:** https://github.com/caterina1974/python-quiz-game
- **개발 환경:** Windows 11, Python 3.10 이상
- **외부 패키지:** 없음 (Python 표준 라이브러리 사용)

## 1. 프로젝트 개요

이 프로젝트는 Python을 처음 배우는 학습자가 기본 문법을 직접 문제로 풀어보며 복습할 수 있도록 만든 콘솔 퀴즈 게임입니다. 메뉴에서 퀴즈 풀기, 퀴즈 추가, 퀴즈 목록 확인, 최고 점수 확인 기능을 선택할 수 있습니다.

프로그램은 객체 지향 구조로 작성했으며, 퀴즈 데이터와 점수를 프로젝트 루트의 `state.json` 파일에 저장합니다. 따라서 프로그램을 종료한 뒤 다시 실행해도 저장된 퀴즈와 점수를 불러올 수 있습니다.

## 2. 퀴즈 주제와 선정 이유

퀴즈 주제는 **Python 기초 문법**입니다. 개발 입문 과정에서 자주 사용하는 출력 함수, 자료형, 형 변환, 조건문, 반복문, 리스트와 딕셔너리 등을 문제로 구성했습니다. 문법을 읽는 데서 끝나지 않고 직접 답을 선택하면서 배운 내용을 확인할 수 있어 이 주제를 선택했습니다.

기본 퀴즈 7개가 제공되며, 프로그램 메뉴에서 학습자가 새로운 문제를 추가할 수 있습니다.

## 3. 개발 환경 및 실행 방법

### 필요한 환경

- Windows 11
- Python 3.10 이상
- Visual Studio Code (선택 사항)
- Git (소스 코드 버전 관리 및 GitHub 업로드용)

외부 Python 패키지를 설치할 필요는 없습니다.

### 실행 방법

1. 저장소를 내려받거나 복제합니다.

   ```powershell
   git clone https://github.com/caterina1974/python-quiz-game.git
   cd python-quiz-game
   ```

2. 프로젝트 폴더에서 다음 명령어를 실행합니다.

   ```powershell
   py -X utf8 main.py
   ```

3. 화면에 표시되는 메뉴에서 원하는 번호를 입력합니다.

   ```text
   1. 퀴즈 풀기
   2. 퀴즈 추가
   3. 퀴즈 목록
   4. 점수 확인
   5. 종료
   ```

`-X utf8` 옵션은 Windows 터미널에서 한글 입출력을 일관되게 처리하는 데 도움이 됩니다.

## 4. 주요 기능

| 기능 | 설명 |
|---|---|
| 퀴즈 풀기 | 저장된 문제를 순서대로 출제하고 정답 여부를 알려줍니다. 모든 문제를 푼 뒤 정답 개수와 점수를 표시합니다. |
| 퀴즈 추가 | 문제, 선택지 4개, 정답 번호(1~4)를 입력하여 새 문제를 등록합니다. |
| 퀴즈 목록 | 저장된 퀴즈의 문제와 선택지를 확인합니다. |
| 점수 확인 | 지금까지 기록한 최고 점수와 해당 기록의 정답 수를 보여줍니다. |
| 자동 저장 | 퀴즈 추가와 게임 결과를 `state.json`에 저장합니다. |
| 입력값 검사 | 빈 입력, 숫자가 아닌 입력, 허용 범위 밖의 숫자를 안내하고 다시 입력받습니다. |
| 안전한 종료 | `Ctrl+C` 또는 입력 스트림 종료(`EOFError`) 상황에서 저장을 시도한 뒤 종료합니다. |
| 데이터 복구 | `state.json`이 없거나 읽을 수 없는 형식이면 기본 퀴즈 데이터로 초기화합니다. |

### 클래스 구성

- **`Quiz`**: 퀴즈 한 문제를 표현합니다. 문제(`question`), 선택지(`choices`), 정답 번호(`answer`)를 관리하고, 문제 출력·정답 확인·딕셔너리 변환 기능을 제공합니다.
- **`QuizGame`**: 게임 전체를 관리합니다. 메뉴 표시, 퀴즈 풀이, 퀴즈 추가, 목록 표시, 점수 확인, JSON 데이터 불러오기와 저장을 담당합니다.

## 6. 데이터 파일 설명: `state.json`

`state.json`은 `main.py`와 같은 프로젝트 최상위 폴더에 생성되는 UTF-8 JSON 파일입니다.

| 키 | 설명 |
|---|---|
| `quizzes` | 퀴즈 목록입니다. 각 항목에는 `question`, `choices`, `answer`가 들어갑니다. |
| `best_score` | 최고 점수(0~100)입니다. |
| `best_correct` | 최고 기록에서 맞힌 문제 수입니다. |
| `best_total` | 최고 기록에서 푼 전체 문제 수입니다. |
| `has_played` | 게임을 한 번이라도 진행했는지 나타내는 값입니다. |

데이터 형태 예시:

```json
{
  "quizzes": [
    {
      "question": "Python에서 화면에 글자를 출력할 때 사용하는 함수는?",
      "choices": ["input()", "print()", "len()", "type()"],
      "answer": 2
    }
  ],
  "best_score": 71,
  "best_correct": 5,
  "best_total": 7,
  "has_played": true
}
```

위 JSON은 데이터 구조를 설명하기 위한 예시입니다. 실제 파일에는 사용자가 추가한 퀴즈와 실제 최고 점수가 저장됩니다.

- 파일이 없으면 기본 퀴즈 데이터로 시작하고 `state.json`을 생성합니다.
- JSON 문법이 잘못되었거나 데이터 구조가 유효하지 않으면 안내 메시지를 표시하고 기본 데이터로 복구합니다.
- 파일 읽기·쓰기 오류는 예외 처리하여 프로그램이 오류 원인을 안내하도록 합니다.

## 7. 자동 테스트

Python 표준 라이브러리인 `unittest`로 `Quiz` 클래스의 동작을 검사합니다. 별도 패키지 설치는 필요하지 않습니다.

프로젝트 최상위 폴더에서 다음 명령어를 실행합니다.

```powershell
py -X utf8 -m unittest discover -s tests -v
```

현재 작성된 테스트는 다음 항목을 확인합니다.

1. 문제 내용 저장
2. 선택지 4개 저장
3. 정답 판정
4. 오답 판정
5. 퀴즈 데이터를 딕셔너리로 변환
6. 잘못된 정답 번호 거부
7. 선택지 개수가 4개가 아닌 경우 거부
8. 빈 문제 내용 거부
9. 딕셔너리 데이터에서 Quiz 객체 복원

테스트 실행 결과는 `Ran 9 tests`와 `OK`로 확인했습니다.

## 11. Git 커밋 이력 및 커밋 규칙

### 11-1. 커밋 이력

본 프로젝트는 기능 구현, 문서 작성, 테스트 추가 및 Git 실습 과정을 단계별 커밋으로 관리했습니다.

README 최종 보완 전 GitHub 저장소에서 총 11개의 커밋을 확인했습니다. README 보완 내용도 별도 커밋으로 추가하여 변경 이력을 관리합니다.

커밋 개수와 상세 이력은 다음 명령어로 확인할 수 있습니다.

```bash
# 전체 커밋 개수 확인
git rev-list --count HEAD

# 최근 커밋 이력 확인
git log --oneline --decorate -12
```

### 11-2. 커밋 메시지 작성 규칙

작업 내용을 쉽게 구분하고 변경 이력을 추적할 수 있도록 다음 형식을 사용합니다.

**작성 형식**

`작업유형: 변경 내용`

| 유형 | 사용 목적 | 작성 예시 |
|---|---|---|
| Init | 프로젝트 초기 설정 | Init: 퀴즈 게임 기본 파일 추가 |
| Feat | 새로운 기능 추가 | Feat: 퀴즈 추가 기능 구현 |
| Fix | 오류 수정 | Fix: 입력값 검증 오류 수정 |
| Docs | 문서 작성 및 수정 | Docs: README 사용 방법 추가 |
| Test | 테스트 추가 및 수정 | Test: Quiz 클래스 단위 테스트 추가 |
| Refactor | 코드 구조 개선 | Refactor: 데이터 처리 코드 정리 |
| Merge | 브랜치 병합 | Merge: 퀴즈 안내 문서를 main에 병합 |

### 11-3. 커밋 관리 원칙

1. 하나의 커밋에는 가능한 한 하나의 논리적인 변경 사항만 포함합니다.
2. 기능 구현, 테스트, 문서 수정은 가능한 한 구분하여 커밋합니다.
3. 커밋 메시지에는 변경 목적과 내용을 간결하게 작성합니다.
4. 변경 사항을 커밋하기 전에 프로그램 실행 및 관련 테스트를 확인합니다.

이러한 규칙을 통해 작업 과정을 추적하기 쉽고, 오류가 발생했을 때 원인을 파악하거나 이전 상태로 되돌리기 쉽도록 관리합니다.
## 12. 객체지향 설계를 선택한 이유

### 12-1. 클래스 기반 설계

본 프로젝트는 `Quiz`와 `QuizGame` 두 클래스를 사용하는 객체지향 구조로 작성했습니다.

- **Quiz 클래스**: 질문, 선택지, 정답 데이터를 관리하고 입력 데이터의 유효성을 검사합니다. 정답 판정과 딕셔너리 변환 기능도 담당합니다.
- **QuizGame 클래스**: 퀴즈 목록, 게임 진행, 점수 관리, 메뉴 처리 및 JSON 데이터 저장·불러오기를 담당합니다.

### 12-2. 객체지향 방식을 선택한 이유

퀴즈 데이터와 게임 진행 기능을 각각 클래스로 묶어 관련 데이터와 기능을 한곳에서 관리할 수 있도록 했습니다.

이렇게 책임을 나누면 코드의 역할을 파악하기 쉽고, 퀴즈 기능이나 게임 기능을 수정할 때 관련 부분을 중심으로 변경할 수 있습니다. 또한 각 클래스의 기능을 독립적으로 테스트하기에도 편리합니다.

### 12-3. 함수 중심 방식과의 비교

함수 중심 방식으로도 퀴즈 게임을 구현할 수 있습니다. 다만 데이터와 관련 기능을 여러 함수에 나누어 전달해야 할 수 있습니다.

반면 객체지향 방식은 퀴즈 데이터와 정답 판정 기능을 `Quiz` 객체에 함께 구성하고, 게임 진행과 저장 관리를 `QuizGame` 객체에 분리할 수 있습니다.

프로젝트 규모와 기능 확장 가능성을 고려하여 객체지향 방식을 선택했습니다.

## 13. Git 브랜치 전략 및 병합 기준

### 13-1. 브랜치 분리 목적

본 프로젝트에서는 기본 작업을 관리하는 `main` 브랜치와 별도의 기능 및 문서 작업을 진행하는 기능 브랜치를 구분했습니다.

예를 들어 퀴즈 풀이 안내 문서를 작성할 때 `feature/quiz-play-guide` 브랜치를 사용했습니다.

기능 브랜치를 사용하는 목적은 다음과 같습니다.

1. 기존 main 브랜치의 안정적인 상태를 유지합니다.
2. 새로운 기능이나 문서 작업을 독립적으로 진행합니다.
3. 작업이 완료된 후 변경 사항을 확인하고 main에 병합합니다.

### 13-2. 병합 기준

기능 브랜치에서 작업을 마치면 다음 사항을 확인한 후 main 브랜치에 병합하는 것을 기준으로 합니다.

- 변경한 기능과 문서가 정상적으로 작성되었는지 확인합니다.
- 프로그램 실행 및 관련 자동 테스트를 확인합니다.
- 기존 기능에 영향을 주는 변경이 없는지 검토합니다.
- 병합 충돌이 발생하면 내용을 비교하고 필요한 부분을 수정한 뒤 병합합니다.

이 프로젝트는 기능별 브랜치를 활용하는 간단한 Feature Branch 전략을 사용했습니다. 모든 작업을 하나의 브랜치에서 진행하는 것보다 변경 내용을 구분하고 작업 이력을 관리하기 쉽다는 장점이 있습니다.
## 14. JSON 데이터 저장 방식과 설계

### 14-1. JSON을 선택한 이유

본 프로젝트에서는 퀴즈 문제와 게임 결과를 저장하기 위해 JSON(JavaScript Object Notation) 형식을 사용했습니다.

JSON은 사람이 읽고 수정하기 쉬운 텍스트 기반 데이터 형식이며, Python의 `json` 모듈을 이용해 별도의 외부 라이브러리 없이 데이터를 저장하고 불러올 수 있습니다.

간단한 콘솔 프로그램에서 데이터를 구조화하고 영속적으로 보관하기에 적합하다고 판단했습니다.

### 14-2. 데이터 필드 구성과 선택 이유

`state.json`은 다음과 같은 정보를 관리합니다.

| 필드 | 역할 | 설계 이유 |
|---|---|---|
| `quizzes` | 퀴즈 목록 | 여러 문제를 하나의 목록으로 관리 |
| `question` | 문제 내용 | 각 퀴즈의 질문을 저장 |
| `choices` | 선택지 목록 | 문제별 네 개의 선택지를 관리 |
| `answer` | 정답 번호 | 사용자의 답과 비교하여 정답 판정 |
| `best_score` | 최고 점수 | 최고 점수를 화면에 표시 |
| `best_correct` | 최고 정답 개수 | 최고 기록의 정답 수 관리 |
| `best_total` | 최고 기록 당시 전체 문제 수 | 점수와 함께 기록의 기준을 보존 |
| `has_played` | 게임 실행 여부 | 게임을 한 번이라도 진행했는지 확인 |

`quizzes`는 여러 퀴즈 객체를 포함하는 목록으로 구성하여 문제 추가와 조회가 편리하도록 했습니다.

현재 저장소의 `state.json`에는 기본 퀴즈 7개와 추가 퀴즈 1개를 합쳐 총 8개가 저장되어 있습니다. 기본 퀴즈 개수와 실제 저장된 전체 퀴즈 개수는 서로 다를 수 있습니다.

### 14-3. JSON 저장 방식의 장점과 한계

**장점**

- 별도의 데이터베이스 서버 설치가 필요하지 않습니다.
- 파일을 직접 열어 데이터 구조를 확인할 수 있습니다.
- Python의 기본 `json` 모듈로 쉽게 읽고 쓸 수 있습니다.
- 소규모 개인 프로젝트에 적은 비용과 복잡도로 적용할 수 있습니다.

**한계**

- 저장할 데이터가 많아지면 파일 전체를 읽고 쓰는 작업으로 인해 처리 시간이 증가할 수 있습니다.
- 파일 전체를 메모리에 불러와 처리하므로 데이터 규모가 커질수록 메모리 사용량이 늘어납니다.
- 여러 사용자가 동시에 같은 파일을 수정하면 데이터가 덮어써지거나 충돌할 가능성이 있습니다.
- 관계형 데이터 검색, 복잡한 조건 검색 및 동시성 관리에 적합하지 않습니다.
- 프로그램이나 컴퓨터에 문제가 발생하면 JSON 파일 자체가 손상될 수 있습니다.

따라서 현재처럼 퀴즈와 점수 기록이 많지 않은 단일 사용자 콘솔 프로그램에는 JSON이 적합하지만, 대규모 데이터나 여러 사용자가 함께 사용하는 서비스로 확장할 경우에는 다른 저장 기술이 필요합니다.

### 14-4. 향후 확장 시 대안

| 저장 기술 | 특징 | 적합한 상황 |
|---|---|---|
| JSON | 간단한 텍스트 파일 기반 저장 | 현재와 같은 소규모 프로젝트 |
| SQLite | 서버 없이 사용하는 파일 기반 관계형 데이터베이스 | 데이터 증가 및 구조적인 검색이 필요한 경우 |
| PostgreSQL | 다중 사용자와 복잡한 데이터 관리 지원 | 여러 사용자가 접속하는 서비스 |
| MySQL | 널리 사용되는 관계형 데이터베이스 | 웹 서비스 및 여러 사용자의 데이터 관리 |

향후 퀴즈 수가 크게 증가하거나 사용자별 기록을 관리해야 한다면 SQLite부터 검토하고, 다중 사용자 서비스로 확장할 때 PostgreSQL이나 MySQL을 고려할 수 있습니다.

### 14-5. 데이터 안전성 및 백업 개선 방향

현재 프로그램은 JSON 파일을 읽거나 쓰는 과정에서 오류가 발생하면 예외를 처리하고 기본 데이터로 복구하는 방식으로 동작합니다.

다만 자동 백업 파일을 별도로 생성하거나 이전 데이터 버전을 복원하는 기능까지 구현한 것은 아닙니다.

따라서 데이터 손실을 줄이기 위한 향후 개선 사항은 다음과 같습니다.

1. 저장하기 전에 기존 `state.json`을 백업 파일로 복사합니다.
2. 임시 파일에 데이터를 먼저 기록한 다음 저장이 완료되면 원본 파일과 교체하는 방식을 적용합니다.
3. 파일 손상 시 백업 파일을 이용해 이전 데이터를 복구할 수 있도록 개선합니다.
4. 저장 전 데이터 구조와 필수 필드의 유효성을 검사합니다.

이러한 개선을 통해 저장 중 오류가 발생하더라도 데이터 손실 가능성을 줄일 수 있습니다.
