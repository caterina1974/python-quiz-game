# 나만의 파이썬 기초 퀴즈 게임

Python 기초 문법을 퀴즈로 복습하고, 사용자가 추가한 문제와 최고 점수를 JSON 파일에 저장하는 콘솔 프로그램입니다.

- **GitHub 저장소:** https://github.com/caterina1974/python-quiz-game
- **개발 환경:** Windows 11, Python 3.10 이상
- **사용 라이브러리:** Python 표준 라이브러리(`json`, `pathlib`, `unittest`)
- **외부 패키지:** 설치 불필요

## 1. 프로젝트 소개 및 개발 목적

이 프로젝트는 Python 입문자가 기초 문법을 직접 문제로 풀면서 학습 내용을 복습할 수 있도록 만든 콘솔 퀴즈 게임입니다. 출력 함수, 자료형, 형 변환, 조건문, 반복문, 리스트와 딕셔너리 등 개발 입문 과정에서 자주 사용하는 내용을 문제로 구성했습니다.

기본 퀴즈 7개를 제공하며, 프로그램 메뉴에서 사용자가 새로운 문제를 추가할 수 있습니다. 현재 저장소의 `state.json`에는 기본 문제 7개와 추가 문제 1개를 합쳐 총 8개가 저장되어 있습니다. 기본 제공 문제 수와 저장 파일에 들어 있는 전체 문제 수는 다를 수 있습니다.

프로그램을 객체지향 구조로 구성하고 JSON 파일을 이용해 퀴즈와 점수를 저장함으로써, 클래스의 책임 분리와 파일 기반 데이터 영속성을 함께 연습하는 것을 목표로 했습니다.

## 2. 주요 기능 및 설계

### 주요 기능

| 기능 | 설명 |
|---|---|
| 퀴즈 풀기 | 저장된 문제를 순서대로 출제하고 정답 여부와 최종 점수를 표시합니다. |
| 퀴즈 추가 | 문제, 선택지 4개, 정답 번호(1~4)를 입력해 새 문제를 등록합니다. |
| 퀴즈 목록 | 저장된 모든 퀴즈의 문제와 선택지를 보여줍니다. |
| 점수 확인 | 최고 점수와 해당 기록의 정답 수 및 전체 문제 수를 표시합니다. |
| 자동 저장 | 퀴즈 추가와 게임 결과를 `state.json`에 저장합니다. |
| 입력값 검증 | 빈 입력, 숫자가 아닌 입력, 허용 범위를 벗어난 숫자를 확인하고 다시 입력받습니다. |
| 오류 처리 | 저장 파일이 없거나 JSON 형식·데이터 구조가 잘못된 경우 안내 메시지를 표시하고 기본 데이터로 초기화합니다. |
| 안전한 종료 | 실행 중 `Ctrl+C` 또는 입력 스트림 종료(`EOFError`)가 발생하면 저장을 시도하고 종료합니다. |

### 클래스 구성과 객체지향 설계

- **`Quiz` 클래스:** 퀴즈 한 문제를 표현합니다. 질문, 선택지, 정답 번호의 유효성을 검사하고 문제 출력, 정답 판정, 딕셔너리 변환 및 객체 복원 기능을 담당합니다.
- **`QuizGame` 클래스:** 퀴즈 목록, 메뉴, 게임 진행, 점수, 데이터 불러오기와 저장 등 게임 전체 흐름을 관리합니다.

퀴즈 한 문제의 데이터와 동작은 `Quiz`에 모으고, 게임의 실행 흐름과 데이터 관리는 `QuizGame`에 나누었습니다. 관련 데이터와 기능을 함께 관리하면 각 클래스의 역할을 파악하고 수정하기 쉬우며, 기능별 테스트와 향후 확장에도 유리합니다.

함수 중심 방식으로도 같은 프로그램을 만들 수 있지만, 데이터와 관련 기능을 여러 함수에 나누어 전달해야 할 수 있습니다. 이 프로젝트는 퀴즈 단위와 게임 관리 단위의 책임을 구분하기 위해 객체지향 방식을 선택했습니다.

## 3. 개발 환경 및 실행 방법

### 필요한 환경

- Windows 11
- Python 3.10 이상
- Git(저장소 복제 및 버전 관리용)
- Visual Studio Code(선택 사항)

외부 Python 패키지를 설치할 필요가 없습니다.

### 저장소 복제 및 실행

PowerShell에서 다음 명령어를 순서대로 실행합니다.

```powershell
git clone https://github.com/caterina1974/python-quiz-game.git
cd python-quiz-game
py -X utf8 main.py
```

`-X utf8` 옵션은 Windows 터미널에서 한글 입출력을 일관되게 처리하는 데 도움이 됩니다.

프로그램이 실행되면 다음 메뉴가 표시됩니다.

```text
1. 퀴즈 풀기
2. 퀴즈 추가
3. 퀴즈 목록
4. 점수 확인
5. 종료
```

## 5. 데이터 저장 방식: `state.json`

### JSON을 선택한 이유

JSON(JavaScript Object Notation)은 사람이 읽기 쉬운 텍스트 기반 데이터 형식입니다. Python의 기본 `json` 모듈로 별도 패키지 없이 데이터를 저장하고 불러올 수 있고, 파일을 직접 열어 구조를 확인하기도 쉽습니다. 퀴즈와 점수처럼 규모가 작은 개인 프로젝트의 데이터를 저장하기에 적합하다고 판단했습니다.

### 데이터 필드

`state.json`은 `main.py`와 같은 프로젝트 최상위 폴더에 UTF-8 형식으로 저장됩니다.

| 필드 | 역할 및 사용 이유 |
|---|---|
| `quizzes` | 퀴즈 목록을 저장합니다. 여러 문제를 하나의 목록으로 관리합니다. |
| `question` | 각 퀴즈의 질문 내용을 저장합니다. |
| `choices` | 문제별 선택지 4개를 목록으로 저장합니다. |
| `answer` | 정답 번호(1~4)를 저장해 사용자 답과 비교합니다. |
| `best_score` | 최고 점수를 저장해 점수 화면에 표시합니다. |
| `best_correct` | 최고 기록에서 맞힌 문제 수를 저장합니다. |
| `best_total` | 최고 기록 당시 전체 문제 수를 저장해 정답 수의 기준을 보존합니다. |
| `has_played` | 게임을 한 번이라도 진행했는지 기록합니다. |

현재 저장소의 `state.json`에는 퀴즈 8개와 최고 점수 71점, 최고 기록 당시 정답 수 5/7이 저장되어 있습니다. 최고 기록 당시의 전체 문제 수(`best_total`)와 현재 퀴즈 개수는 기록 시점이 다를 수 있으므로 서로 다를 수 있습니다.

### 저장 및 복구 동작

- `state.json`이 없으면 기본 퀴즈 7개로 시작하고 파일을 생성합니다.
- JSON 문법이나 데이터 구조가 잘못된 경우 오류 안내 후 기본 퀴즈와 초기 점수로 복구합니다.
- 파일 읽기 중 `OSError`, `json.JSONDecodeError`, `ValueError`, `TypeError`, `KeyError` 등이 발생하면 예외를 처리하고 기본 데이터로 초기화합니다.
- 저장할 때는 UTF-8 인코딩과 `ensure_ascii=False`를 사용해 한글이 읽을 수 있는 형태로 기록합니다.

### JSON 저장 방식의 장점과 한계

**장점**

- 별도의 데이터베이스 서버가 필요하지 않습니다.
- 사람이 파일을 직접 열어 데이터를 확인하고 수정할 수 있습니다.
- Python 표준 라이브러리만으로 읽기와 쓰기를 구현할 수 있습니다.
- 데이터 규모가 작은 단일 사용자 프로그램에 간단하게 적용할 수 있습니다.

**한계**

- 데이터가 커지면 파일 전체를 읽고 쓰는 데 시간이 더 걸릴 수 있습니다.
- 파일 전체를 메모리에 불러와 처리하므로 데이터가 커질수록 메모리 사용량도 증가합니다.
- 여러 사용자가 같은 파일을 동시에 수정하면 변경 내용이 덮어써지거나 충돌할 수 있습니다.
- 복잡한 조건 검색, 관계형 데이터 관리, 동시 사용자 처리가 필요한 서비스에는 적합하지 않습니다.
- 저장 도중 프로그램이나 컴퓨터에 문제가 발생하면 파일이 손상될 가능성이 있습니다.

현재처럼 퀴즈와 점수 기록이 많지 않은 단일 사용자 프로그램에는 JSON이 적합합니다. 데이터가 증가하거나 사용자별 기록과 동시 접근이 필요해지면 SQLite, PostgreSQL, MySQL 등의 데이터베이스를 검토할 수 있습니다. SQLite는 소규모 확장에, PostgreSQL과 MySQL은 여러 사용자가 접속하는 서비스에 고려할 수 있습니다.

### 데이터 안전성 개선 방향

현재 프로그램은 읽기 오류가 발생하면 기본 데이터로 복구하지만, 자동 백업 파일 생성이나 과거 데이터 버전 복원 기능은 구현되어 있지 않습니다. 또한 현재 저장은 `state.json` 파일에 직접 기록하는 방식입니다.

향후 데이터 손실 위험을 줄이기 위해 다음 개선을 고려할 수 있습니다.

1. 새 데이터를 저장하기 전에 기존 파일을 백업합니다.
2. 임시 파일에 먼저 기록하고 저장 성공 후 원본과 교체하는 방식을 적용합니다.
3. 파일 손상 시 백업 파일에서 복구할 수 있는 절차를 추가합니다.
4. 저장 전 데이터 구조와 필수 필드의 유효성을 검사합니다.

위 항목은 향후 개선 방향이며, 현재 구현된 기능과 구분해 기술했습니다.

## 6. 자동 테스트

Python 표준 라이브러리 `unittest`를 사용해 `Quiz` 클래스의 기본 동작을 확인합니다. 별도 패키지 설치는 필요하지 않습니다.

프로젝트 최상위 폴더에서 다음 명령어를 실행합니다.

```powershell
py -X utf8 -m unittest discover -s tests -v
```

현재 `tests/test_quiz.py`에는 다음 9개 테스트가 있습니다.

1. 문제 내용 저장
2. 선택지 4개 저장
3. 정답 판정
4. 오답 판정
5. 퀴즈 데이터를 딕셔너리로 변환
6. 잘못된 정답 번호 거부
7. 선택지 개수가 4개가 아닌 경우 거부
8. 빈 문제 내용 거부
9. 딕셔너리 데이터에서 `Quiz` 객체 복원

실행 결과는 `Ran 9 tests`와 `OK`로 확인했습니다. 현재 자동 테스트는 `Quiz` 클래스의 단위 테스트에 초점을 두며, 실제 키보드 입력을 포함한 메뉴 전체 흐름은 별도 실행 확인이 필요합니다.

### 브랜치 전략과 병합 기준

기본 작업은 `main` 브랜치에서 관리하고, 별도의 기능이나 문서 작업은 기능 브랜치에서 진행하는 Feature Branch 방식을 사용했습니다. 예를 들어 퀴즈 풀이 안내 문서를 `feature/quiz-play-guide` 브랜치에서 작성한 후 `main` 브랜치에 병합했습니다.

브랜치를 나누는 이유는 기존 `main`의 안정적인 상태를 유지하면서 새 작업을 독립적으로 진행하고, 변경 내용을 검토한 뒤 통합하기 위해서입니다. 기능 브랜치에서 작업을 마치면 문서와 코드 변경을 확인하고, 프로그램 실행 및 관련 테스트를 점검한 뒤 병합하는 것을 기준으로 합니다. 충돌이 발생하면 충돌 파일의 변경 내용을 비교해 필요한 부분을 정리한 후 병합합니다.

또한 저장소를 별도 폴더에 `clone`하고, 복제한 폴더에서 README를 수정해 `push`한 다음 원래 작업 폴더에서 `pull`하여 원격 변경 내용이 반영되는 과정을 확인했습니다.

커밋 메시지는 다음 형식을 기준으로 작성합니다.

`작업유형: 변경 내용`

| 유형 | 사용 목적 | 예시 |
|---|---|---|
| `Init` | 프로젝트 초기 설정 | `Init: 퀴즈 게임 기본 파일 추가` |
| `Feat` | 새 기능 추가 | `Feat: 퀴즈 추가 기능 구현` |
| `Fix` | 오류 수정 | `Fix: 입력값 검증 오류 수정` |
| `Docs` | 문서 작성 및 수정 | `Docs: README 사용 방법 추가` |
| `Test` | 테스트 추가 및 수정 | `Test: Quiz 클래스 단위 테스트 추가` |
| `Refactor` | 코드 구조 개선 | `Refactor: 데이터 처리 코드 정리` |
| `Merge` | 브랜치 병합 | `Merge: 퀴즈 안내 문서를 main에 병합` |

커밋 관리 원칙은 다음과 같습니다.

1. 하나의 커밋에는 가능한 한 하나의 논리적인 변경 사항만 포함합니다.
2. 기능 구현, 테스트, 문서 수정은 가능한 한 구분해 커밋합니다.
3. 커밋 메시지는 변경 목적과 내용을 간결하게 표현합니다.
4. 커밋 전에 프로그램 실행과 관련 테스트를 확인합니다.

## 8. 요구사항 변경 시 수정 위치

새로운 요구사항이 생기면 관련 파일과 메서드를 확인한 뒤 수정합니다. 아래 표는 현재 코드 구조를 기준으로 한 변경 위치 안내입니다.

| 변경하려는 내용 | 파일 | 수정 위치 |
|---|---|---|
| 퀴즈 생성 규칙 및 데이터 검증 | `main.py` | `Quiz.__init__()` |
| 문제와 선택지 출력 | `main.py` | `Quiz.display()` |
| 정답 판정 | `main.py` | `Quiz.is_correct()` |
| 퀴즈 데이터 변환·복원 | `main.py` | `Quiz.to_dict()`, `Quiz.from_dict()` |
| 기본 문제 추가·변경 | `main.py` | `QuizGame.make_default_quizzes()` |
| 빈 문자열 입력 검증 | `main.py` | `QuizGame.read_non_empty()` |
| 숫자와 입력 범위 검증 | `main.py` | `QuizGame.read_number()` |
| 데이터 불러오기와 오류 복구 | `main.py` | `QuizGame.load_data()` |
| 데이터 저장 방식 | `main.py` | `QuizGame.save_data()` |
| 메뉴 구성 및 메뉴 흐름 | `main.py` | `QuizGame.show_menu()`, `QuizGame.run()` |
| 퀴즈 진행 및 점수 계산 | `main.py` | `QuizGame.play_quiz()` |
| 새 퀴즈 등록 | `main.py` | `QuizGame.add_quiz()` |
| 퀴즈 목록 표시 | `main.py` | `QuizGame.show_quizzes()` |
| 최고 점수 표시 | `main.py` | `QuizGame.show_score()` |
| 저장 파일 위치 | `main.py` | `STATE_FILE` 상수 |
| 프로그램 시작 및 중단 처리 | `main.py` | `main()` 함수 |
| 퀴즈 단위 테스트 | `tests/test_quiz.py` | `TestQuiz` 클래스의 테스트 메서드 |

### 변경 예시 1. 선택지를 4개에서 5개로 늘리는 경우

- `Quiz.__init__()`에서 선택지 개수 검증을 변경합니다.
- `QuizGame.add_quiz()`에서 선택지를 5개 입력받도록 반복 범위를 변경합니다.
- `QuizGame.play_quiz()`에서 정답 입력 범위를 1~5로 변경합니다.
- `tests/test_quiz.py`에서 선택지 개수와 정답 판정 테스트를 수정합니다.
- README의 기능 설명과 입력 안내도 5개 기준으로 갱신합니다.

### 변경 예시 2. 최고 점수 기록 방식을 바꾸는 경우

- `QuizGame.play_quiz()`에서 점수 계산과 최고 점수 갱신 방식을 확인합니다.
- `QuizGame.save_data()`와 `QuizGame.load_data()`에서 저장·불러오기 구조를 함께 확인합니다.
- `state.json`의 데이터 구조가 변경되면 기존 데이터와의 호환성을 검토합니다.

### 변경 후 검증 순서

1. 관련 메서드와 데이터를 수정합니다.
2. `tests/test_quiz.py`에 필요한 테스트를 추가하거나 수정합니다.
3. 다음 명령으로 자동 테스트를 실행합니다.

   ```powershell
   py -X utf8 -m unittest discover -s tests -v
   ```

4. 프로그램을 직접 실행해 메뉴, 입력, 저장 및 불러오기 기능을 확인합니다.
5. README와 관련 문서를 실제 코드 상태에 맞게 갱신합니다.
6. 변경 내용을 확인한 후 Git 커밋으로 기록합니다.
